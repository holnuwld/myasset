# 서브에이전트 협업 및 인계 프로토콜 (Handoff Protocol)

## 1. 문서 기반 인계 (Spec-Driven Workflow)
모든 작업은 아래 순서로 진행되며, `docs/` 디렉토리의 문서를 단일 진실 공급원(Single Source of Truth)으로 삼습니다.

1. **[비서 → `architect`]**: 요구사항 변경 또는 신규 기능 도입 시 `docs/sheet_schema.md` 및 `docs/alert_rules.md`를 먼저 갱신합니다.
2. **[비서 → `developer`]**: 갱신된 `docs/` 명세를 근거로 구현 대상 파일과 완료 조건(DoD)을 명시하여 지시합니다.
3. **[비서 → `qa-verifier`]**: `developer`의 구현 완료 후 테스트 실행 및 엣지 케이스 검증을 지시합니다.
4. **[비서 → 사용자]**: `qa-verifier`의 검증 통과 확인 후 `docs/task_board.md`를 업데이트하고 사용자에게 보고합니다.

## 2. 서브에이전트 보고 양식
각 서브에이전트는 작업 완료 후 비서에게 다음 항목을 포함하여 보고합니다.
- **수행 요약**: 완료한 작업 핵심 요약 (3줄 이내)
- **변경/참조 파일**: 생성·수정한 파일 경로 및 주요 함수/클래스명
- **검증 결과**: 실행한 명령어/테스트 결과 및 통과 여부
- **이슈/블로커**: 추가 결정이 필요한 사항 (없으면 `없음`)
