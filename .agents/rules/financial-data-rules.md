# 금융 데이터 및 보안 하네스 규칙 (Financial Data & Security Rules)

이 워크스페이스의 모든 에이전트(`architect`, `developer`, `qa-verifier`, `asset-monitor`)는 자산 관리 프로그램 설계·구현·검증 시 다음 규칙을 엄격히 준수해야 합니다.

## 1. 자격 증명 및 개인정보 보호 (Security Guardrails)
- Google Cloud 서비스 계정 키(`credentials.json`, `service_account.json`), OAuth 토큰, 외부 API 키, 알림 봇 토큰(Telegram/Slack 등), 실제 계좌번호가 포함된 파일은 절대 소스 코드에 하드코딩하거나 Git에 커밋하지 않습니다.
- 모든 민감 설정은 `.env` 또는 환경 변수로 주입받도록 구현하고, `.gitignore`에 인증 파일 패턴을 반드시 등록합니다.

## 2. 금액·수익률·비율 계산 정합성
- **부동소수점 오차 방지**: 통화 금액, 이율($\%$), 자산 배분 비율($\%$) 계산 시 부동소수점(`float`) 반올림 오차가 누적되지 않도록 `Decimal` 타입(또는 정수 원화 단위 연산)을 사용합니다.
- **배분 비율 무결성**: 카테고리별 자산 배분 비율의 총합은 반올림 보정 후 항상 $100.00\%$가 되어야 하며, 총자산이 $0$원인 경우 ZeroDivisionError가 발생하지 않도록 예외 처리합니다.
- **통화 구분**: 원화(`KRW`)와 외화(`USD` 등) 자산이 혼재할 경우 기준 통화 환산 금액 컬럼을 기준으로 비중을 계산합니다.

## 3. 시간대 및 만기일 계산 규칙
- 모든 날짜 및 만기일(D-Day) 계산은 한국 표준시(`Asia/Seoul`, KST) 자정을 기준으로 처리합니다.
- 실시간 주가 조회 실패(휴장일, 네트워크 오류, 잘못된 티커) 시 프로그램이 중단되지 않고 직전 종가 또는 시트 내 기존 가격을 유지하며 경고 로그를 남겨야 합니다.
